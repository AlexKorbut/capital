# КАПИТАЛЬ как модуль хоста (Джарвис)

КАПИТАЛЬ — самостоятельное приложение. Хост (например, Джарвис) не встраивает его
код, а **запускает его как процесс и разговаривает с ним по HTTP**. Этот документ
описывает контракт, на который опирается хост. Контракт не привязан к Джарвису:
любой хост, умеющий читать JSON и слать `Authorization: Bearer`, подойдёт.

## 1. Обнаружение: манифест модуля

`GET {base_url}/api/v1/module` — публичный, без авторизации, статический:

```json
{
  "name": "kapital",
  "title": "КАПИТАЛЬ",
  "version": "0.1.0",
  "api_prefix": "/api/v1",
  "auth": { "scheme": "bearer", "token_prefix": "kp_", "setup_path": "/settings" },
  "health": "/api/v1/health",
  "openapi": "/openapi.json",
  "capabilities": [
    "portfolio.read", "portfolio.write", "goals", "advice", "scenarios", "wallets",
    "finance.projects", "finance.expenses", "finance.reports", "finance.attachments"
  ],
  "limits": {
    "attachment_max_bytes": 10485760,
    "attachment_mime": ["image/jpeg", "image/png", "image/webp"]
  }
}
```

Хост читает манифест один раз при подключении: откуда брать API, как
авторизоваться, где опрашивать здоровье и где лежит схема OpenAPI.

`capabilities` только растёт: новые возможности добавляются, существующие не
убираются и не переименовываются. `finance.projects`, `finance.expenses` и
`finance.reports` — финансовые проекты, `finance.attachments` — фото чеков к тратам
(раздел 4а). `limits` — жёсткие пределы, которые хост может показать пользователю до
загрузки; поле только добавляется.

## 2. Здоровье

`GET /api/v1/health` → `{"status": "ok", "environment": ..., "db": ..., "demo_mode": ...}`.
Хост считает модуль живым при `200` и `status == "ok"`.

## 3. Авторизация: персональный API-токен

Машинный клиент не логинится паролем и не проходит 2FA. Пользователь один раз
создаёт **персональный API-токен** в интерфейсе КАПИТАЛЯ (Настройки → «API-токены»)
и отдаёт его хосту. Токен показывается один раз; в базе хранится только SHA-256.

- Формат: `kp_` + 43 URL-safe символа.
- Использование: `Authorization: Bearer kp_…` на любой ручке под `/api/v1`, так
  же, как JWT-сессия браузера. Ручки, доступные токену, — все пользовательские
  ручки (портфель, цели, советник, сценарии, кошельки, аккаунт).
- Отзыв: `DELETE /api/v1/account/tokens/{id}` (или кнопка «Отозвать» в
  настройках). После отзыва токен отвечает `401`.
- «Выйти везде» (`/auth/logout-all`) токены **не** отзывает: они живут до явного
  отзыва. Удаление аккаунта удаляет и токены.
- `last_used_at` обновляется не чаще раза в минуту.

Ручки управления (нужна сессия пользователя или другой токен):

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/v1/account/tokens` | активные токены: `id`, `name`, `prefix`, `created_at`, `last_used_at` (секрета нет) |
| `POST` | `/api/v1/account/tokens` `{"name": "…"}` | создаёт токен; ответ `201` содержит `token` — единственный раз |
| `DELETE` | `/api/v1/account/tokens/{id}` | отзыв; `204`; чужой или уже отозванный — `404` |

## 4. Чтение и запись данных

Хост пользуется обычным API КАПИТАЛЯ (см. `/openapi.json`). Типичный минимум:

- `GET /api/v1/portfolio/current` — текущий портфель и net worth в базовой валюте;
- `GET /api/v1/portfolio/history/chart`, `GET /api/v1/portfolio/returns` — динамика;
- `GET /api/v1/goals` — цели;
- `POST /api/v1/portfolio/input` `{"text": "…"}` → превью → `POST /api/v1/portfolio/confirm` — запись новых активов тем же путём, что из интерфейса;
- `POST /api/v1/portfolio/assets`, `PATCH /api/v1/portfolio/assets/{id}` — точечные правки.

Лимиты запросов (slowapi) действуют и для токенов.

## 4а. Финансовые проекты (`/api/v1/finance`)

Проект собирает траты в любых валютах («Машина»: бензин в BYN, страховка в EUR,
запчасти в USD) и считает отчёт в валюте проекта. Каждая трата хранится в своей
валюте **и** в валюте проекта по курсу на дату траты — отчёт не зависит от курса
«сегодня». Авторизация — как везде (JWT или токен `kp_`); всё по пользователю,
чужой проект или трата отвечают `404`. Деньги в JSON — строки (`"110.00"`), курсы
без хвостовых нулей (`"1.1"`). Тело запроса строгое: неизвестное поле — `422`.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/finance/projects?status=active\|archived` | проекты с итогами: `total_base`, `expenses_count`, `last_spent_on`, `unpriced_count` |
| `POST` | `/finance/projects` | `name`, `base_currency` (по умолчанию базовая валюта пользователя), `started_on?`, `note?`; `409` — такое название уже есть |
| `GET` `PATCH` `DELETE` | `/finance/projects/{id}` | смена `base_currency` пересчитывает траты; удаление — вместе с тратами |
| `GET` | `/finance/projects/{id}/expenses?from&to&category&currency&limit&offset` | `{items, total, limit, offset}`; `limit` ≤ 200, новые сверху |
| `POST` | `/finance/projects/{id}/expenses` | `amount`, `currency`, `spent_on`, `category?`, `note?`, `fx_rate?`, `client_id?` |
| `PATCH` `DELETE` | `/finance/expenses/{id}` | правка пересчитывает курс (см. ниже) |
| `GET` | `/finance/projects/{id}/report?from&to` | итоги: `total_base`, `unpriced_by_currency[]`, `by_category[]`, `by_month[]`, `by_currency[]` |
| `POST` | `/finance/projects/{id}/revalue` | досчитать траты «без курса» → `{revalued, unpriced_count}` |
| `GET` | `/finance/fx?currency&date&base` | предпросмотр курса для формы: `{rate, fx_date, source}` |
| `GET` | `/finance/categories` | подсказки: категории пользователя по частоте, затем стандартные |
| `POST` | `/finance/expenses/{id}/attachments` | фото чека: `multipart/form-data`, поле `file` → `201 {id, mime, size_bytes, created_at, original_name}` |
| `GET` | `/finance/attachments/{id}` | сама картинка (байты) |
| `DELETE` | `/finance/attachments/{id}` | `204`: удаляет и строку, и файл |

**Траты.** `amount` ≠ 0 (отрицательная — возврат), `|amount|` ≤ 10^12, не больше 6
знаков после запятой; `currency` — код ISO-4217 из трёх латинских букв; `spent_on`
не раньше 1970-01-01 и не позже завтрашнего дня. `category` приводится к нижнему
регистру («Топливо» = «топливо»). Повтор `POST` с тем же `client_id` возвращает ту
же трату (`200`, без дубля) — хост может безопасно повторять запрос; тот же
`client_id` в другом проекте — `409`.

**Курс.** В ответе траты: `base_amount` (в валюте проекта, округление до 0,01 вверх
от половины), `fx_rate` (единиц валюты проекта за 1 единицу валюты траты), `fx_date`
(дата, на которую курс действует на самом деле: у траты в воскресенье это пятница),
`fx_source` — `ecb`, `nbrb`, `nbg`, `cbr`, `manual` или `latest`.

| Валюта | Источник курса на дату |
|---|---|
| USD | курс 1, источник не нужен |
| BYN | НБРБ, только с 2016-07-01 (раньше — деноминация, курса нет) |
| GEL | НБГ |
| RUB | ЦБ РФ, официальный `cbr.ru/scripts/XML_daily.asp`: курс, **действующий** на любую дату (суббота, воскресенье, праздники тоже); `fx_date` — дата, с которой он действует (5 января → курс от 30 декабря) |
| AUD BGN BRL CAD CHF CNY CZK DKK EUR GBP HKD HUF IDR ILS INR ISK JPY KRW MXN MYR NOK NZD PHP PLN RON SEK SGD THB TRY ZAR | ЕЦБ через Frankfurter, с 1999-01-04 (BGN — только до перехода Болгарии на евро) |
| остальные коды ISO | курса на дату нет: трата сохраняется «без курса» |

Порядок поиска: таблица `fx_rates_daily` (точная дата) → провайдер (полученный курс сохраняется
вместе с остальной записью запроса, одной транзакцией) → **только если провайдер ответил «на эту
дату данных нет»** (404, пустой ответ): ближайший прежний курс из таблицы не старше 7 дней (с его
датой), а для сегодняшней и завтрашней траты — обычный текущий курс (`latest`) → «без курса»:
`base_amount`, `fx_rate`, `fx_date`, `fx_source` равны `null`, трата сохраняется, итоги её не учитывают,
а `unpriced_count` её считает. Курс, который провайдер выдал «на дату», считается действующим и под
7-дневное ограничение не подпадает; оно относится только к запасному курсу из таблицы.
Ответ «данных нет» запоминается на 10 минут (по паре валюта + дата), `revalue` спрашивает заново.

**Сбой провайдера — не «нет данных».** Таймаут, сеть, ответ 5xx, ответ не того вида, вышедший бюджет
времени: трата сохраняется «без курса» (`base_amount = null`), без тихого запасного курса из таблицы
и без `latest` — потом `POST /finance/projects/{id}/revalue` её досчитает. Ретраи — только на сеть
и 5xx; любой 4xx (в первую очередь 404) повторно не запрашивается.

Курс между двумя не-USD валютами считается через USD. Свой курс — `fx_rate` в теле траты
(`fx_source = "manual"`): единиц валюты проекта за 1 единицу валюты траты; для траты в самой валюте
проекта он игнорируется. `PATCH` с `fx_rate: null` возвращает рыночный курс.

**Смена базовой валюты проекта** пересчитывает все траты. Ручной курс сохраняется (он переводится
через курс старой валюты проекта в новую на дату траты), если такой курс найден. Что не успело
пересчитаться в бюджет времени, становится «без курса»; ответ `PATCH` содержит `unpriced_count`.
**После смены валюты при `unpriced_count > 0` вызовите `POST /finance/projects/{id}/revalue`**
(при необходимости несколько раз, пока `unpriced_count` не станет 0). `revalue` пишет только в траты
без цены (`UPDATE … WHERE base_amount IS NULL`) и не затирает цену, которую владелец успел поставить сам.

**Время.** Все внешние запросы одного вызова делят бюджет в 4 секунды (прокси Джарвиса отвечает за 5).

**Лимиты** считаются по пользователю (JWT-сессия и токен `kp_` — одна корзина), а не по IP: хост ходит
с одного адреса за всех своих пользователей. Запись (`POST`/`PATCH` проектов и трат) — 60 в минуту,
`GET /finance/fx` — 60 в минуту, `POST …/revalue` — 10 в минуту, загрузка вложения — 20 в минуту,
чтение вложения — 120 в минуту; сверх лимита — `429`.

**Вложения (фото чеков).** К трате можно приложить до 5 фото. В ответах трат (`GET
/finance/projects/{id}/expenses`, создание и правка) есть поле `attachments: [{id, mime, size_bytes,
created_at}]` (без имени файла); в списке проектов и в отчёте счётчика вложений нет.

- *Размер.* Не больше 10 МБ (`limits.attachment_max_bytes`): ровно 10 МБ проходит, на один байт больше —
  `413`. Отказ приходит, как только лимит превышен, остаток тела не читается; заявленный `Content-Length`
  больше 10 МБ плюс 64 КБ на служебную часть multipart — `413` до чтения тела.
- *Тип.* Определяется только по первым байтам файла: JPEG (`FF D8 FF`), PNG, WEBP (`RIFF` + размер
  + `WEBP` + первый блок `VP8 `/`VP8L`/`VP8X`; размер в заголовке должен укладываться в файл).
  Имя файла и заявленный `Content-Type` не учитываются. Остальное, включая HEIC, пустой файл и
  подделку, — `415` «поддерживаются JPEG, PNG и WEBP — сожмите фото на телефоне».
- *Повтор и пределы.* Тот же файл к той же трате — `200` с прежним вложением (повторять запрос
  безопасно, и это проверяется раньше любых пределов); шестое разное вложение к трате — `409`.
  На пользователя: не больше 1000 вложений (`409`) и 500 МБ суммарно (`413`, «Достигнут предел хранилища
  вложений…»); удаление вложений освобождает место. Трат на пользователя — не больше 20 000 (`409`;
  повтор `POST` с уже известным `client_id` предел не трогает).
- *Чтение.* `GET /finance/attachments/{id}` отдаёт байты с серверным `Content-Type`,
  `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`,
  `Content-Security-Policy: default-src 'none'; sandbox` и
  `Content-Disposition: inline; filename="receipt.<jpg|png|webp>"` — имя клиента в заголовок не попадает.
  Нужен заголовок `Authorization`, поэтому хост отдаёт картинку через прокси, а не прямой ссылкой в `<img>`;
  кэш не используется (`no-store`), так что после удаления картинка нигде не остаётся.
  Перед выдачей длина и sha256 файла сверяются с записью: если файл повреждён или зашифрован другим
  ключом (потерян `FERNET_KEY`), ответ — `500 «вложение повреждено или ключ не тот»`, а не мусор вместо картинки.
  Файл, записанный до включения шифрования, читается как обычно.
- *Имя.* `original_name` (имя, которое дал клиент: без пути, до 200 символов) есть только в ответе на
  загрузку и в экспорте и нужно лишь для показа. Путь хранения строит сервер из id
  (`u/{user_id}/{expense_id}/{attachment_id}.{ext}`), от клиента в него ничего не попадает.
- *Хранение.* Каталог `UPLOADS_DIR` (по умолчанию `backend/uploads`; в Docker — том `uploads`). Если задан
  `FERNET_KEY`, байты на диске и `original_name` в базе зашифрованы. **В production без `FERNET_KEY` загрузка
  отвечает `503` «хранилище вложений не настроено (FERNET_KEY)»** (чтение и удаление работают); в разработке без
  ключа файлы лежат открытыми, при старте в лог пишется одна строка-предупреждение. Резервная копия:
  `scripts/backup.sh` кладёт архив тома рядом с дампом базы.
- *Нагрузка.* Одновременно обрабатывается не больше 4 загрузок; если место не освободилось за 15 секунд —
  `503 «Сервер занят загрузками…»`, запрос можно повторить. Тело запроса должно прийти целиком за 120 секунд,
  иначе `408`. Если клиент оборвал соединение, запрос заканчивается тихо (`499`, это не ошибка сервера).
  Чтение картинки — 120 в минуту на пользователя.
- *Удаление.* Удаление траты или проекта удаляет и файлы — после успешного commit; удаление аккаунта
  убирает всю папку пользователя `u/{user_id}` целиком (в том числе оборванные записи `*.tmp`). Если файл
  или папка не удалились, в лог идёт строка без путей и имён, ответ остаётся успешным.

**Строки.** Название проекта, категория и заметка нормализуются (Unicode NFC; в названии и категории
пробельные серии схлопываются, категория — в нижний регистр) и только потом проверяются на длину
(120 / 60 / 2000). Символ `\x00` в любой строке — `422`.

**Аккаунт.** Экспорт (`GET /account/export`) содержит `fin_projects`, `fin_expenses`, `fin_attachments`
(метаданные вложений: без байтов и без внутреннего ключа хранилища; а также `goals`, `wallets` и
`scenarios`); удаление аккаунта удаляет их и файлы вложений — сначала вложения, потом траты, потом проекты.

## 5. Модели: чьи ключи

КАПИТАЛЬ вызывает языковые модели сам, через свой провайдер-агностичный слой
(`core/llm.py`). У пользователя два режима (Настройки → «Искусственный интеллект»,
`GET/PUT /api/v1/account/ai`):

- **`kapital`** (по умолчанию) — ключи сервера КАПИТАЛЯ («ИИ КАПИТАЛЯ», входит в
  подписку). Если на сервере ключей нет, ИИ-функции работают в демо-режиме.
- **`own`** — ключи самого пользователя (Anthropic, OpenAI, Google, Groq).
  Хранятся зашифрованными (Fernet, `FERNET_KEY`), наружу отдаются только в виде
  маски `…wxyz`. В этом режиме ключи сервера **никогда** не используются: нет
  ключа для провайдера роли — роль работает как демо-заготовка.

`PUT /api/v1/account/ai` принимает `{"mode": "own"|"kapital", "keys": {"anthropic": "sk-…"}}`;
`null` или пустая строка удаляет ключ. Ответ содержит `demo` — работает ли сейчас
разбор ввода как заготовка.

Хост, у которого есть свой шлюз моделей, может выдать пользователю ключ к нему и
прописать его как «свой ключ» подходящего провайдера (шлюз должен говорить на
API этого провайдера). Так КАПИТАЛЬ остаётся независимым, а хост — хозяином
расходов.

## 6. Запуск под хостом

Минимальный автономный запуск без Docker (SQLite, планировщик в процессе):

```bash
cd backend
.venv\Scripts\python -m alembic upgrade head
.venv\Scripts\python -m uvicorn main:app --port 8010
```

Хосту нужны только `base_url` (`http://127.0.0.1:8010`) и токен. Переменные
окружения — как в `.env.example`; для работы под хостом достаточно `DATABASE_URL`,
`JWT_SECRET`, `FERNET_KEY`. Интерфейс (`frontend/`) запускается отдельно и нужен
пользователю для создания токена и ввода ключей.
